A comment on LinkedIn said that if I was still shaping the [AI Engineering](https://datatalks.club/academy/ai-engineering/) track, a module on the data side would make it stand out: ingestion, freshness and evaluation datasets. That is where a lot of production systems break first.

I looked at the draft syllabus on the course page. Module 02 already has a first ingestion pipeline: you produce a one-command load and a knowledge assistant with sources. The evaluation modules use an evaluation set, but they do not ask you to build or maintain one. Freshness is not on the page at all. The comment was right about the gap.

## Options

I compared three ways to add this work, and I kept the program at 13 weeks and 16 modules. The interview block in weeks 10 to 13 stays. The agentic engineering module already in this track also stays.

A new full week would come out of the squad project or out of the early retrieval weeks, which are already in preparation. That is too much weight for one data module.

Only extending the existing modules would leave the page looking the same, and the new work would be easy to drop when a week runs late.

I chose a named module in the Quality and production block, after the assistant is deployed, so freshness actually matters. To keep 16 modules, I merged the current module 09, Testing LLM Applications and CI/CD, with module 10, Evaluating Answers and Agents.

## The Module

The new module 09 is Data Pipelines, Freshness and Evaluation Datasets. It covers three things:

1. Incremental ingestion: add, update and remove documents without rebuilding the index.
2. Freshness: how old the index is, and what the assistant says when its data is stale.
3. Evaluation datasets: build a set from real questions and documents, add synthetic cases for the gaps, and version it when the documents change.

You produce a pipeline that keeps your assistant's index up to date, with a freshness report, and a versioned evaluation dataset for your project.

The merged module 10 is Testing and Evaluating Answers and Agents. You produce a regression suite running in CI and an evaluation report comparing two configurations.

I also made small line edits in modules 02 and 04, so the first ingestion can be rerun safely and the first evaluation dataset appears when retrieval is evaluated. The outcomes on the page will mention keeping the index up to date and building evaluation datasets. Item 02 still includes document processing. The final project now uses internal documents that keep changing.
